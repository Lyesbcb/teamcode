# V1 review checklist

This is a review of the working foundation, not a declaration that V1 release acceptance is complete. Start with [current progress](progress.md), [verified evidence](status.md) and the [TeamClaude gap ledger](teamclaude-comparison.md).

## Walk through the implemented product

1. Deploy the chart against a test MySQL database and keep its encryption key across restarts. Confirm the image commit associated with the successful build; `latest` advances only after every required CI job passes.
2. Use the one-time bootstrap administrator password, change it, create a member in the dashboard and sign in as that member. Confirm there is no public signup and administrative pages are unavailable to the member.
3. Set the self-hosted URL with `teamcode login --server https://your-host`. Restart the CLI and check that authentication and the URL persist. Confirm password replacement and session revocation.
4. As the administrator, inspect `teamcode accounts import --from teamclaude --dry-run`. For a temporary trial while TeamClaude remains the refresh owner, import with `--access-only`. Verify repeated import updates the same identities and preserves account settings. A permanent switch uses explicit refresh handover after the old refresher is stopped.
5. Exercise `teamcode accounts add --provider claude` and `--provider codex`. Codex's direct browser consent is the outstanding live enrollment check: paste the complete callback URL into the hidden prompt. Check reconnect/upsert and explicit ownership after enrollment.
6. Set member weights, concurrency and pool budgets in the dashboard. Set allowed models/efforts, including the decision about Fable. Confirm a rejected policy is visible to the caller and does not dispatch a provider request.
7. Run `teamcode run claude -- ...` and `teamcode run codex -- ...` with a small request. Confirm request/provider/model/account metadata and settled usage in the server logs without prompts or credentials.
8. On a test workstation, run `teamcode service install`, then test reuse, stop/start/restart/uninstall. Actual Windows lifecycle CI and actual workstation reboot/logon evidence are separate checks; consult their latest recorded status.
9. Configure a fallback route in the dashboard. First use the documented portable profile with reasoning explicitly disabled and standard function tools or the documented supported custom text formats. Confirm the destination model, then deliberately test unsupported features and inspect the error instead of assuming conversion is lossless.
10. Occupy physical capacity using controlled requests from multiple members. Check waiting counts, member turn rotation and background aging using `run claude/codex --workload background -- ...` or the workload header. Confirm a background launch sharing the service does not change an interactive launch's class. Cancel a pending request before any response headers and confirm its metadata disappears without reserved credits. Exercise the authenticated cancellation endpoint through another replica while the original inference connection stays open, both before headers and during streaming. Test policy/session revocation while pending. Upgrade all replicas and the local CLI before expecting this behavior end to end.

## Decisions and evidence still needed for a full V1

- **Full agent portability:** complete coding tasks are verified in both directions with reasoning disabled: Claude built-in Read/Edit/Bash and Codex namespaced/code-mode tools, including `additional_tools` and replayed custom tool calls. Finish full-default-client and reasoning acceptance. Both clients also complete a task after the native provider is disabled at a tool-result boundary, using the unchanged fallback route. These controlled portable-profile tasks do not prove every route or an actual quota/reset boundary. Opaque signed/encrypted reasoning, hosted tools and unsupported custom grammars remain explicit limitations. Native passthrough retains their original fields; crossing protocols does not currently preserve every such feature.
- **Session behavior:** shared SQL affinity and model-specific failover are implemented and integration-tested; finish real-agent quota/reset-boundary acceptance without changing an active tool conversation incompatibly.
- **Capacity control:** shared bounded scheduling has independent-pool MySQL tests for turn fairness, background aging, isolation, cancellation and policy rechecks. Native workload selection passed Linux and Windows CI. Shared cancellation control has real HTTP/MySQL replica tests and native macOS/Linux evidence; updated Windows cancellation runtime acceptance remains pending. Finish real-load fairness/polling-cost acceptance, soft borrowing and reconciliation, remaining provider-specific quota shapes, real quota/reset-boundary acceptance, real Codex Windows hooks, subagent fan-out and real-load forecast replay stability. Percentages from different plans are not interchangeable team credits.
- **Team administration:** finish groups, devices and scoped service credentials with revocation/audit acceptance.
- **Distribution and operations:** add versioned native distribution, update/rollback, pre-login service support, clean-machine reboot/logon and database restore/performance evidence.

Open-source model providers and centralized MCP and skill administration remain V2. None of these remaining gates is removed merely because the foundation or a platform CI run is green.
